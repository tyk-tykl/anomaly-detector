# Детектор аномалий

Веб-приложение на Streamlit для поиска необычных транзакций. Позволяет запустить один из четырёх алгоритмов, посмотреть найденные аномалии с объяснением, почему они выделились, и сравнить алгоритмы между собой по качеству и времени работы.

Основной набор данных проекта — [Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud). Но приложение не привязано к нему: оно принимает любой CSV, в том числе с датами и текстовыми столбцами (страна, магазин, категория).

## Возможности

- Загрузка собственного CSV-файла с транзакциями
- Четыре алгоритма: **Z-score**, **Isolation Forest**, **LOF** (Local Outlier Factor), **One-Class SVM**
- Выбор столбцов в боковой панели: какие использовать как признаки и какой столбец является меткой (необязательно)
- Автоматическая подготовка: даты превращаются в час и день недели, текстовые столбцы кодируются частотой встречаемости (редкий магазин или страна получают малое значение)
- Логарифм суммы (`log1p`) — галочка, включена по умолчанию
- Список аномалий, отсортированный по Score, с колонкой «Почему аномально» (три признака с наибольшим отклонением)
- Метрики качества (Precision, Recall, F1-score) и матрица ошибок, если выбран столбец с меткой 0/1
- Режим «Сравнить все алгоритмы»: оценка на отложенной выборке, 5 запусков с разным разбиением, среднее и стандартное отклонение, PR-кривая, время работы
- Выгрузка в Excel (.xlsx): найденные аномалии и (для файлов до 100 000 строк) весь файл со Score и Anomaly
- Результат сравнения автоматически сохраняется в `results/comparison.csv`

## Данные

Датасет Kaggle: около 284 тысяч транзакций, из них мошеннических около 0,17%. Столбец `Class` содержит 1 для мошеннических и 0 для обычных транзакций. Признаки `V1`–`V28` получены преобразованием PCA (исходные поля банк скрыл), плюс `Time` (секунды от начала выборки) и `Amount` (сумма).

В исходном файле 1081 полный дубликат строк. Для итоговых результатов использовался файл без дубликатов: 283 726 строк, из них 473 мошеннических.

Сам датасет в репозиторий не включён из-за размера (около 150 МБ). Скачайте `creditcard.csv` и положите его в `data/raw/`. Файл без дубликатов можно получить так:

```python
import pandas as pd
df = pd.read_csv("data/raw/creditcard.csv").drop_duplicates()
df.to_csv("data/processed/creditcard_clean.csv", index=False)
```

### Демонстрационный файл

Для проверки работы с «реальным» форматом (дата, сумма, страна, магазин, категория, клиент) есть генератор синтетических данных:

```bash
python scripts/make_demo.py
```

Он создаёт `data/demo/transactions_demo.csv` (5 000 строк, из них 100 с заложенными аномалиями, метка в столбце `is_fraud`). Аномалии в нём очевидные, поэтому метрики на нём высокие. Это проверка функций приложения, а не научный результат.

## Запуск

Из корня проекта:

```bash
streamlit run app.py
```

Приложение откроется в браузере (обычно по адресу http://localhost:8501). Загрузите CSV, при необходимости выберите столбец с меткой и признаки в боковой панели, выберите алгоритм и нажмите «Запустить анализ» или «Сравнить все алгоритмы». Остановить приложение: `Ctrl+C` в терминале.

Вспомогательные скрипты (работают из любой папки):

```bash
python scripts/inspect_data.py        # осмотр исходного датасета

python scripts/visualize_results.py   # графики из results/comparison.csv
python scripts/run_experiment.py      # эксперимент с признаками и вариантами Z-score
```

`visualize_results.py` нужно запускать после того, как в приложении выполнено «Сравнить все алгоритмы».

## Как это работает

1. **Подготовка.** Из выбранных столбцов строится числовая таблица признаков: числа берутся как есть, даты дают час и день недели, текст кодируется частотой. Если включена галочка логарифма, столбец `Amount` заменяется на `log1p(Amount)`. Пропуски заполняются медианой, признаки масштабируются `StandardScaler`. Столбец с меткой в признаки не попадает.
2. **Поиск аномалий.** Алгоритм считает Score (чем выше, тем необычнее запись) и помечает транзакцию как обычную (0) или аномальную (1).
3. **Объяснение.** Для каждой найденной аномалии показываются три признака с наибольшим отклонением от среднего (в стандартных отклонениях σ). Это приближённое объяснение, а не внутренняя логика модели.
4. **Оценка качества.** Данные делятся на обучающую (80%) и проверочную (20%) части. Модель учится на первой, метрики считаются на второй. Это повторяется 5 раз с разным разбиением.

### Алгоритмы и параметры

| Алгоритм | Параметры | Как помечается аномалия |
|---|---|---|
| Z-score | порог 3 | максимум \|z\| по всем признакам больше 3 |
| Isolation Forest | параметры scikit-learn по умолчанию | оценка модели ниже нуля |
| LOF | `n_neighbors=20`, `novelty=True`, обучение на подвыборке до 5000 записей | оценка модели ниже нуля |
| One-Class SVM | ядро RBF, `nu=0.05`, обучение на подвыборке до 2500 записей | оценка модели ниже нуля |

Подвыборки нужны, потому что LOF и One-Class SVM слишком медленные на больших файлах.

### Метрики

Precision, Recall и F1 зависят от порога: разные алгоритмы помечают разное число записей. Поэтому в сравнении есть и метрики, не зависящие от порога:

- **Avg Precision** — площадь под PR-кривой.
- **ROC-AUC** — вероятность того, что мошенническая транзакция получит Score выше обычной. При доле мошенничества 0,17% он оптимистичен: огромное число обычных транзакций делает ложные срабатывания «дешёвыми».
- **Precision@1% и Recall@1%** — качество среди 1% транзакций с самым высоким Score. Показывает, сколько мошенничества найдёт аналитик, проверив одинаковое число самых подозрительных записей.

Столбцы со знаком `±` — стандартное отклонение по 5 запускам. Столбец «Время (сек.)» — среднее на один запуск.

## Результаты

Датасет без дубликатов (283 726 строк), `log1p(Amount)`, проверочная выборка 56 746 записей (около 95 мошеннических), среднее по 5 запускам. Полная таблица: `results/comparison.csv`.

| Алгоритм | Avg Precision | ROC-AUC | Precision@1% | Recall@1% | F1 | Время, с |
|---|---|---|---|---|---|---|
| Z-score | 0.098 ± 0.015 | 0.942 | 0.092 | 0.552 ± 0.066 | 0.023 | 0.51 |
| Isolation Forest | 0.144 ± 0.017 | 0.947 | 0.096 | 0.573 ± 0.022 | 0.072 | 1.00 |
| LOF | **0.339 ± 0.073** | **0.951** | **0.138** | **0.823 ± 0.032** | 0.053 | 0.85 |
| One-Class SVM | 0.121 ± 0.029 | 0.948 | 0.115 | 0.684 ± 0.091 | 0.042 | 2.66 |

Основные наблюдения:

- **LOF лидирует** по Avg Precision и Recall@1%: проверив 1% самых подозрительных транзакций, он находит около 82% мошенничества против 55–57% у Z-score и Isolation Forest. Разрыв с One-Class SVM меньше, и там вывод менее надёжен.
- **Лидер по F1 зависит от порога.** По F1 лучший Isolation Forest, но это следствие того, что он помечает меньше записей (около 2 100 против 3 000–3 900). Без привязки к порогу лидером оказывается LOF.
- **По ROC-AUC методы почти не различаются** (0.942–0.951), поэтому основными метриками сравнения выбраны Avg Precision и Recall@1%.
- **Порог по умолчанию даёт слишком длинные списки.** На всём файле LOF помечает около 6% записей при доле мошенничества 0,17%, поэтому полезен в первую очередь верх списка по Score.

Эксперимент с признаками (`results/experiment_features.csv`):

- `log1p(Amount)` ничему не навредил и слегка улучшил Isolation Forest, у остальных методов изменения в пределах разброса.
- Замена `Time` на час суток результата не изменила.
- Z-score только по `Amount` почти бесполезен (Avg Precision 0.003): одной суммы недостаточно.
- Робастный Z-score (медиана и MAD) оказался хуже обычного.

На Kaggle-датасете эффект от преобразований признаков небольшой, потому что 28 из 30 признаков — уже готовые PCA-компоненты.

## Ограничения

- Модель глобальная и не знает, что одна и та же сумма нормальна для одного клиента и необычна для другого: признаков «на клиента» пока нет.
- Логарифм применяется только к столбцу с названием `Amount`.
- Аномалия не обязательно мошенничество: это запись, необычная с точки зрения выбранного метода.
- Метрики после обычного анализа считаются на всём файле, который модель уже видела, поэтому они оптимистичнее, чем в режиме сравнения. Для LOF и One-Class SVM это усиливается: записи обучающей подвыборки оцениваются «сами с собой».
- Метрики на малом числе мошеннических записей (около 95 в проверке) шумные, поэтому выводы делаются по среднему и разбросу, а не по одному запуску.
- Демонстрационный файл синтетический.

## Используемые технологии

Python, Streamlit, pandas, NumPy, scikit-learn, Altair (графики в приложении), Matplotlib (графики в скриптах), openpyxl (выгрузка в Excel).

## Идеи для развития

- Настройка параметров алгоритмов в боковой панели: порог Z-score, `n_neighbors`, `nu`, доля помечаемых аномалий
- Сравнение результатов методов: сколько записей нашли два и более метода (основа для ансамбля)
- Признаки клиента: отклонение суммы от обычных трат этого клиента
- ROC-кривая по скорингу моделей
- Выбор столбца суммы для логарифма
- Загрузка из Excel и подключение базы данных (PostgreSQL)
- Тесты для модулей в `src/`
